# Module ownership and invariant map

Status: describes the current owners. It is not a claim that every normative fault is covered; coverage below is bounded to the cited tests.

## Frontend

| Owner                                                                                   | Responsibilities                                                                                                                                                                                                                                                                                                          | Must not own                                                               |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `apps/web/src/main.tsx` bootstrap (54 lines)                                            | Mount and error boundary only                                                                                                                                                                                                                                                                                             | Selection, shortcuts, transport, filesystem or Pi access                   |
| `apps/web/src/app/App.tsx` plus `app/use-*.ts`                                          | Selection and draft transitions, command-result completion, global shortcut/Escape priority, feature composition (named hooks such as `use-app-state`, `use-global-shortcuts`, `use-selection-sync`)                                                                                                                      | Authentication transport, replay/outbox internals, filesystem or Pi access |
| `apps/web/src/store.ts` plus `store/{internal,subscriptions,commands,socket,upload}.ts` | `store.ts` composes the store; `socket` owns HTTP/WS transport, renewal and projection buffering, invalidation and event reduction, `subscriptions` selection and stream subscribe/unsubscribe requests, `commands` the durable client outbox and command submission, `upload` attachment upload, `internal` shared state | Feature rendering, popup focus policy, per-component editor state          |
| `domain/presentation.ts`                                                                | Pure transcript/tool/usage/age projection and labels                                                                                                                                                                                                                                                                      | React state, transport, persistence                                        |
| `components/ui.tsx`                                                                     | Disclosure, picker, icon and action-error primitives through narrow props                                                                                                                                                                                                                                                 | Store/transport access                                                     |
| `features/transcript/index.tsx`                                                         | Stable message/block rendering and keys, lazy rich presentation, activity disclosure and transcript-local lookup                                                                                                                                                                                                          | New connections, catalog selection mutation                                |
| Composer coordinator                                                                    | Draft/attachment/queue/run controls and selection flush as one transition                                                                                                                                                                                                                                                 | Direct replay or authentication state mutation                             |
| Workspace owners                                                                        | Files, current Git changes and terminal adapters; review opens only on explicit activation                                                                                                                                                                                                                                | Project/session lifecycle or unrestricted paths                            |

Feature modules receive narrow typed operations and projections. They do not receive the complete store or a general setter bag. Cross-feature implementation imports are private; another feature may use only a public `index` entrypoint (for example the header imports `features/updates/index.ts`). Feature implementations never import the `app/` layer; the application layer may coordinate genuine cross-feature transitions.

## Host

| Owner                                                                                  | Responsibilities                                                                                                                                                                                                                                                    | Ordering invariant                                                                                                                                          |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `AsyncJobOwner`                                                                        | Accepted asynchronous completion lifetime, terminal receipt persistence, publication and shutdown drain                                                                                                                                                             | Accepted-before-close work always reaches a durable terminal receipt before publish; unpersistable completion fails the shutdown drain                      |
| Runtime supervisor `host-runtime.ts`, `host-message-writes.ts`, `host-interactions.ts` | Pi child/boot/retirement/submission state (`host-runtime`), pending image/transcript writes plus transcript batching and flushes (`host-message-writes`), pending extension interactions and expiry (`host-interactions`); `host-work.ts` projects protected work   | Runtime, terminal, pending transcript and artifact work is counted; every owned exit/write is awaited before storage/lock release                           |
| Stream publisher `host-stream.ts`                                                      | WebSocket stream subscriptions, the durable-first publish and fanout (including terminal fanout), subscriber backpressure and catalog phase publication; replay continuity and snapshot fallback live in `host-ws.ts`                                               | Contiguous sequence; final/error boundaries flush immediately                                                                                               |
| Command and job leaves                                                                 | `host-commands-{assets,catalog,files,import,pi,run,session,settings}.ts` (wired by `host-wiring.ts`) and `host-jobs-{run,session}.ts`; `host-queue.ts` owns queue shadows, `host-queue-workers.ts` and `host-session-broker.ts` the review-queue workers and broker | Leaves receive narrow capabilities (`host-caps.ts`), never the host context                                                                                 |
| Transport/control wiring                                                               | Loopback Host/Origin/cookie/CSRF/nonce checks, control socket, instance identity and shutdown ingress                                                                                                                                                               | Authentication before command ingress; stopping rejects writes/bootstrap, retains bounded health, and closes control only after storage/lock ownership ends |
| `Resources`                                                                            | Root descriptor/no-follow file operations and PTY ownership                                                                                                                                                                                                         | No path capability expansion from client text; PTY shutdown owns and awaits terminal exit                                                                   |
| `host-contract.ts`                                                                     | Pure host identity, bounded parsing and queueability constants                                                                                                                                                                                                      | Storage, process or transport mutation                                                                                                                      |
| `local-release.ts`                                                                     | Content-addressed private release staging, atomic activation and validated rollback                                                                                                                                                                                 | User-data deletion or package publication                                                                                                                   |
| `Assets`, `UiBuilds`, adapter                                                          | Private artifacts/icons, immutable UI releases, Pi translation                                                                                                                                                                                                      | No UI/Pi types cross protocol boundaries                                                                                                                    |

Host transport is split into private owners wired by `host.ts`: `host-transport.ts` (client secrets, bootstrap nonces, WS restart bindings, authentication), `host-http.ts` (HTTP server and listen/close operations), `host-ws.ts` (event WebSocket server, replay continuity check and snapshot fallback) and `host-grants.ts` (the single owner of consumable path and runtime-validation grants shared by HTTP, control and commands). Control is split into `host-control.ts` and `host-control-restart.ts`. Subscriptions are owned by `host-stream.ts`; the WS module receives only register/remove/subscribe/unsubscribe operations.

Owners expose operations and narrow capabilities, not mutable Maps or a shared mutable host context.

### Preserved contracts

These six behaviors were reviewed and deliberately kept; each has a focused test and no product change.

- Validation polling: `runtime.validate` resubmits the identical envelope until a terminal receipt. Command reservation dedupes before job creation, so identical polls start exactly one validation job and consume the grant once. Test: [`cp2-contracts`](../tests/integration/cp2-contracts.test.ts) "identical runtime validation polls start exactly one job".
- History import denial: an incompatible header or a header whose `cwd` does not resolve to the selected workspace is a bounded `PATH_DENIED` with no row, directory or filesystem detail. A history file the OS refuses to read is not part of that mapping; it stays the bounded generic internal error. Tests: [`cp2-contracts`](../tests/integration/cp2-contracts.test.ts) "unreadable import history is denied without filesystem details" and "OS-denied history reads retain the bounded generic error".
- Text writes: `file.write` is update-only. It needs the current revision, replaces an existing regular file through the no-follow descriptor path and never creates a file or follows a symlink. Test: [`cp2-contracts`](../tests/integration/cp2-contracts.test.ts) "file writes update existing text and never create or follow symlinks".
- Binary targets: a binary file rejects text writes with `CONFLICT` for any revision, leaving bytes, directory listing and catalog head unchanged. Test: [`cp2-contracts`](../tests/integration/cp2-contracts.test.ts) "binary targets reject text writes without mutation".
- Icon clear: `icon.clear` requires the current `expectedRevision`; a missing or stale value is `CONFLICT` with state and catalog head unchanged, and the current revision clears exactly once. Test: [`cp2-contracts`](../tests/integration/cp2-contracts.test.ts) "icon clear requires the current revision for project and session".
- Bootstrap nonces: a nonce is single use and is consumed even when rejected for age (rejected only when `expires < now`; the sixty-second edge is still valid). Expired or replayed nonces answer 401 with no `Set-Cookie` and no client session. Tests: [`host-concurrent-renewal`](../tests/integration/host-concurrent-renewal.test.ts) "expired and replayed nonces never issue cookies or client sessions" and "rejects a bootstrap nonce after sixty seconds and consumes it even when rejected".

### Transport, completion and artifact boundaries

Bounded to the cited tests; this is not a claim of exhaustive fault coverage.

- Transport (`host-transport.ts`, `host-ws.ts`, `host-stream.ts`): sockets are tracked per authenticated secret with one expiry timer per secret. Renewal reschedules only the presented secret; expiry or revocation closes only that secret's sockets with 1008, and inbound subscription and fanout paths check authorization without renewing. Failed CSRF never renews a cookie. Tests: [`host-concurrent-renewal`](../tests/integration/host-concurrent-renewal.test.ts), [`host-transport-sockets`](../tests/unit/host-transport-sockets.test.ts).
- Completion (`AsyncJobOwner`, `Storage`): accepting an async command records a side `async_completions` marker, leaving existing tables unchanged for older host builds. A host that stops before saving a completion recovers the marked receipt once as `ASYNC_INTERRUPTED` with its result event, and unresolved completions count as blockers in health. A rejected `close()` stays fail-closed and a later `close()` retries the drain. Tests: [`cp2-completion-recovery`](../tests/integration/cp2-completion-recovery.test.ts), [`storage`](../tests/unit/storage.test.ts), [`async-jobs`](../tests/unit/async-jobs.test.ts), [`host-completion-storage-failure`](../tests/integration/host-completion-storage-failure.test.ts).
- Artifacts (`Assets`, `host-message-writes.ts`): `artifact.get` requires an owning session. A blob is committed with its row and `artifact.ready`; a failure removes only the blob that attempt created, and a failed large-output artifact keeps the original message text with an "attachment not saved" notice. Tests: [`assets`](../tests/unit/assets.test.ts), [`host-completion-storage-failure`](../tests/integration/host-completion-storage-failure.test.ts).
- Admission and drain (`host.ts`, `host-runtime.ts`, `host-message-writes.ts`): a run submission is a reaper-protected owner before prompt preparation and is released on failure; a `session.resume` during boot joins that boot; `close()` awaits accepted image writes and their continuations, publishes their frames before storage closes and rejects later emissions. Tests: [`host-retirement-collisions`](../tests/integration/host-retirement-collisions.test.ts), [`host-message-writes`](../tests/unit/host-message-writes.test.ts).

## Package dependency edges and public surfaces

Packages are relative-source workspaces whose `package.json` `exports` maps (no wildcards) declare the public surface; other packages and apps import only those targets, by relative path or package name.

| Package       | Public entrypoints                                                                                                                        | Private implementation                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `protocol`    | `.`, `./updates`, `./update-checkpoint`, `./update-commands`                                                                              | none                                                          |
| `pi-adapter`  | `.` (Pi client, translator), `./review-queue` (queue runtime/host/worker profile), `./review-queue-extension` (runtime-loaded executable) | `review-queue-{runtime,host,worker}.ts`, `runtime-version.ts` |
| `model-chain` | `.`, `./adapters` (chain adapters), `./broker` (broker framing)                                                                           | `broker-framing.ts`, `runner.ts`                              |

Allowed edges: host → {protocol, pi-adapter, model-chain}, web → protocol, pi-adapter → {protocol, model-chain}; `protocol` and `model-chain` import no sibling and no package imports an app. `pi-adapter` → `model-chain` is deliberate broker-client reuse by the review-queue extension, which imports the `./adapters` entrypoint; it is not an upward edge. The host imports `./review-queue` and `./broker` rather than `review-queue-*` or `broker-framing` internals. The review-queue extension file path (`pi-adapter/src/review-queue-extension.ts`) is a runtime-loaded executable and is unchanged.

## Dependency enforcement

`npm run lint` runs `scripts/check-boundaries.mjs` (logic in `scripts/boundaries-lib.mjs`) over every `packages/*/src` plus `apps/web/src` and `apps/host/src`. It resolves emitted `.js`/`.mjs`/`.cjs` specifiers to sources and rejects unresolved relative imports, forbidden package and app edges, imports that bypass a package's `exports` map, Node/Pi imports in web/protocol code, private cross-feature imports, feature imports of `app/`, import cycles, wildcard exports, and product sources over 400 physical lines (CSS 600; named exceptions for `host.ts`, `cli-migrate.ts`, `pi-client.ts`, `review-queue-runtime.ts` and `dsh-file-icons.tsx`). `tests/unit/boundaries-negative.test.ts` proves each rule rejects its isolated fixture and that the paired public cases pass. `npm run lint` also runs `scripts/check-exports.mjs`, a compiler export inventory: every export of `apps/` and `packages/` that no product file references must appear in its exact `{file, symbol, reason}` allowlist (runtime roots, public package surface, named test seams), and an allowlist entry that no longer matches a finding fails as stale. These are structural guards, not a substitute for runtime characterization.

## Portable verification

`npm run format:portable` checks only non-native source. `npm run verify:portable` runs formatting, lint, types, build, unit and RPC tests, integration, then browser and accessibility checks. It does not read or invoke the native shell or packaging checks.
